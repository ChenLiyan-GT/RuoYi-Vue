# Harness Engineering L

## 目标

- 形成工程级文档的最终层，覆盖项目交付、质量保障、发布和运维。
- 定义文档治理、版本管理、发布流程与持续更新机制。
- 为项目团队提供统一的工程文档标准与维护策略。

## 工程治理

### 文档维护规范

- 所有工程文档统一存放于 `ruoyi-admin/.gientech/wiki/`
- 新文档必须添加到 `目录.md` 中，确保索引可访问
- 文档更新时应同步记录引用文件路径和版本信息

### 版本管理

- 项目版本由根 `pom.xml` 中 `<version>4.8.3</version>` 确定
- Wiki 文档应注明对应版本和发布日期
- 新功能或架构调整必须更新 `项目概述.md`、`架构总览.md` 与 `部署与运维.md`

## 发布与交付

### 构建流程

- 使用 Maven 构建：`mvn clean package -DskipTests`
- 或使用脚本：`bin/package.bat`
- 构建产物位于子模块 `target/` 目录下

### 运行部署

- 本地开发：`./ry.sh start`
- Windows 运行：`bin\run.bat`
- 访问端口：`80`
- 常用入口：`/swagger-ui.html`, `/v3/api-docs`, `/druid/`

### 发布检查项

- 确认 `application.yml` 与 `application-druid.yml` 配置正确
- 确认数据库已经导入初始化数据
- 确认日志与监控入口可访问

## 质量控制

### 测试策略

- 已存在 `测试策略.md`，应覆盖单元测试、集成测试和回归测试指南
- 项目建议执行以下命令进行基本验证：
  - `mvn test`
  - `mvn verify`

### 代码规范

- 遵循现有 `编码指引.md` 中的命名、注释、异常处理和安全规范
- 重点关注：Shiro 权限边界、MyBatis SQL 映射、XSS 过滤、文件上传限制

### 文档审查

- 新增或变更文档应由至少一名团队成员 review
- 文档内容需与实际代码路径保持一致

## 运维与监控

### 关键监控点

- Druid 监控：数据库连接池状态
- SpringDoc：API 接口可见性
- 日志文件：`logback.xml` 中日志级别配置

### 故障排查

- 启动失败：检查数据库连接、端口冲突、JVM 参数
- 登录失败：检查 Shiro 登录路径与会话配置
- 权限问题：检查角色、菜单、数据权限关联表

## 知识闭环

### 文档更新流程

1. 代码变更时同步更新相关文档
2. 修改 `目录.md` 以反映新增文档
3. 在变更说明中注明文档作者与更新时间

### 维护建议

- 定期审查 Wiki 文档与实际代码的一致性
- 通过 `Harness L` 三层结构保持工程文档完整性
- 对关键模块和业务链路进行定期复盘与更新
