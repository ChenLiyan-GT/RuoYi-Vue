# Harness Engineering L3

## 目标

- 形成工程级文档第三层（L3），覆盖成熟运维、发布治理与持续改进。
- 将项目的架构、质量、交付和运维要求纳入统一的工程运行闭环。
- 提供可执行的发布检查、回滚策略、生产环境保障与关键指标监控。

## 适用范围

- 项目交付后期：上线验证、运维支持、问题反馈与稳定性保障。
- 版本发布过程：构建、部署、回滚、发布审批与发布后监控。
- 运行治理：安全、日志、审计、告警与运维自动化。

## 关键内容

### 1. 发布管理

- 发布版本由根 `pom.xml` `<version>` 决定，建议关闭 SNAPSHOT 发布到生产。
- 发布流程应包含：构建验证、Smoke Test、变更审查、发布审批、回滚准备。
- 使用 `mvn clean package -DskipTests` 生成构建产物，二次验证 `ruoyi-admin/target/` 目录产物。
- 发布后验证点：应用启动正常、接口健康、登录流程、核心功能（用户、权限、菜单）可用。

### 2. 回滚与风险控制

- 生产发布前准备：备份数据库、备份配置文件、记录已发布版本。
- 回滚方案：如发布失败或业务异常，立即回退到上一个已验证版本，恢复数据库快照或变更。
- 风险控制清单：配置错误、数据库连接失败、权限异常、API 响应异常、静态资源丢失。

### 3. 运行监控与报警

- 关键监控点：应用启动状态、数据库连接池、Shiro 认证状态、请求成功率、错误率、慢 SQL。
- 监控页面：`/druid/`、`/swagger-ui.html`、日志文件 `logback.xml` 配置输出路径。
- 建议配置告警：新增异常日志、HTTP 500 频次、登录失败率、缓存异常、数据库连接数阈值。

### 4. 质量保障

- 发布前执行：`mvn test`、`mvn verify`、接口 Smoke Test、权限链路验真。 
- 文档复核：检查 `目录.md`、`架构总览.md`、`部署与运维.md`、`测试策略.md` 是否与实际代码和配置保持一致。
- 变更说明：新功能或修复应补充 `项目概述.md`、`架构总览.md`、`部署与运维.md` 以及 `Harness L*` 文档。

### 5. 运维支持

- 运行环境要求：JDK 17、MySQL 5.7+、Maven 3.6+、80 端口可用。
- 运行方式：`./ry.sh start` / `ry.bat start` / `java -jar ruoyi-admin.jar`
- 运维常用命令：检查进程、查看日志、清理缓存、重启服务。

### 6. 安全与审计

- 安全检查项：Shiro 登录与权限策略、验证码启用、Sensitive 信息保护、XSS 和文件上传限制。
- 审计记录：登录日志、操作日志、数据权限操作要可追踪。
- 文档要求：将安全策略要点写入 `部署与运维.md`、`编码指引.md` 以及 `Harness L3.md`。

### 7. 持续改进

- 反馈机制：每次发布后收集问题清单，形成归档和复盘报告。
- 文档迭代：根据运行问题优化 `目录.md`、`测试策略.md`、`部署与运维.md`、`Harness L*` 文档。
- 持续交付建议：建立版本发布流水线，优化构建、测试、部署、回滚与监控闭环。
