## 概述

本文档定义了 RuoYi 项目的编码规范和最佳实践，旨在确保代码质量、可维护性和团队协作效率。所有开发人员必须严格遵循本规范，通过代码审查和自动化工具确保规范的执行。

项目基本信息：
- **项目名称**：RuoYi（若依）
- **版本**：4.8.3
- **技术栈**：Spring Boot 3.5.14 + JDK 17 + MyBatis + Shiro + Druid
- **项目类型**：轻量级 Java 快速开发框架
- **核心功能**：提供用户管理、部门管理、岗位管理、菜单管理、角色管理、字典管理、参数管理、系统监控、代码生成等后台管理系统核心功能

项目详细信息参考 [README.md](../../../README.md)。

### 核心原则
- **可读性优先**: 代码应该易于理解和维护
- **一致性**: 保持代码风格和结构的一致性
- **简洁性**: 避免过度复杂的设计和实现
- **安全性**: 遵循安全编码最佳实践
- **性能**: 在保证可读性的前提下优化性能

## 代码风格规范

### 基本格式规范

#### 缩进和空格
- 使用 4 个空格进行缩进
- 行尾不允许有空格
- 文件末尾保留一个空行
- 每行代码长度不超过 120 个字符

#### 大括号规范
```java
// 推荐：大括号不换行
public class ExampleClass {
    public void method() {
        if (condition) {
            // 代码逻辑
        }
    }
}

// 不推荐：大括号换行
public class ExampleClass
{
    public void method()
    {
        if (condition)
        {
            // 代码逻辑
        }
    }
}
```

#### 空行规范
- 类成员之间使用一个空行分隔
- 方法之间使用一个空行分隔
- 逻辑块之间使用空行提高可读性
- 导入语句分组，组间使用空行分隔

### 导入语句规范

```java
// 1. Java 标准库
import java.util.List;
import java.util.Map;

// 2. 第三方库
import org.springframework.stereotype.Service;
import org.springframework.beans.factory.annotation.Autowired;

// 3. 项目内部包
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.system.domain.SysUser;
```

## 命名规范

### 类命名规范

#### 类名
- 使用 PascalCase（首字母大写的驼峰命名）
- 类名应该是名词，具有描述性
- 避免缩写，除非是广泛认知的缩写

```java
// 推荐 - 参考项目实际类
public class SysUser { }
public class SysMenu { }
public class SysRole { }

// 不推荐
public class SUser { }
public class SMenu { }
public class SRole { }
```

#### 接口命名
- 接口名通常以描述性名词
- 接口实现类添加"Impl"后缀

```java
// 推荐 - 参考项目实际结构
public interface ISysUserService { }
public class SysUserServiceImpl implements ISysUserService { }
```

### 方法命名规范

#### 方法名
- 使用 camelCase（首字母小写的驼峰命名）
- 方法名应该是动词或动词短语
- 布尔方法使用 is、has、can 等前缀

```java
// 推荐
public void createUser(SysUser user) { }
public List<SysUser> selectUserList(SysUser user) { }
public boolean checkUserNameUnique(SysUser user) { }
public boolean hasPermission(String permission) { }

// 不推荐
public void userCreate(SysUser user) { }
public List<SysUser> getUsers(SysUser user) { }
public boolean checkUser(SysUser user) { }
```

### 变量命名规范

#### 变量名
- 使用 camelCase
- 变量名应该具有描述性
- 避免使用单字母变量名（除了循环变量）

```java
// 推荐
String userName = "admin";
List<SysUser> userList = new ArrayList<>();
int maxRetryCount = 5;

// 不推荐
String u = "admin";
List<SysUser> list = new ArrayList<>();
int n = 5;
```

#### 常量命名
- 使用 UPPER_SNAKE_CASE
- 常量名应该具有描述性

```java
// 推荐 - 参考项目实际常量
public static final String USER_ROLE = "admin";
public static final int MAX_LOGIN_ATTEMPTS = 5;
public static final String SUCCESS = "success";
```

## 代码结构规范

### 类结构规范

#### 类成员顺序
```java
public class ExampleClass {
    // 1. 静态常量
    private static final String CONSTANT = "value";

    // 2. 静态变量
    private static int staticVariable;

    // 3. 实例变量
    private String instanceVariable;

    // 4. 构造函数
    public ExampleClass() { }

    // 5. 静态方法
    public static void staticMethod() { }

    // 6. 实例方法
    public void instanceMethod() { }

    // 7. 私有方法
    private void privateMethod() { }
}
```

### 方法结构规范

#### 方法长度
- 单个方法不超过 80 行
- 如果方法过长，考虑拆分为多个小方法
- 每个方法只做一件事

#### 参数规范
- 方法参数不超过 5 个
- 如果参数过多，考虑使用参数对象
- 使用 Builder 模式处理复杂参数

```java
// 推荐：使用参数对象
public void createUser(UserCreateRequest request) {
    // 实现逻辑
}

// 不推荐：参数过多
public void createUser(String name, String email, String phone,
                      String address, String role, boolean active) {
    // 实现逻辑
}
```

### 包结构规范

项目采用标准的多层架构，包结构如下：

```
com.ruoyi
├── RuoYiApplication.java          # 启动类
├── common/                        # 通用模块
│   ├── annotation/               # 自定义注解

│   ├── core/                     # 核心类
│   ├── enums/                    # 枚举类
│   ├── exception/                # 异常类
│   ├── json/                     # JSON 处理
│   ├── utils/                    # 工具类
│   └── xss/                      # XSS 防护
├── system/                        # 系统模块
│   ├── domain/                   # 实体类
│   ├── mapper/                   # 数据访问层
│   └── service/                  # 服务层
└── web/                           # Web 模块
    └── controller/               # 控制器层
        ├── common/               # 通用控制器
```

各层职责：
- **controller 层**：处理 HTTP 请求，调用 service 层，返回响应结果
- **service 层**：业务逻辑处理，调用 mapper 层
- **mapper 层**：数据库访问操作
- **domain 层**：数据模型定义
- **common 层**：通用工具、常量、异常、配置等

### 行内注释规范

#### 注释原则
- 解释"为什么"而不是"做什么"
- 避免显而易见的注释
- 注释应该与代码同步更新

```java
// 推荐：解释业务逻辑
// 检查用户是否在试用期内，试用期用户有特殊限制
if (user.isInTrialPeriod() && user.getUsageCount() > TRIAL_LIMIT) {
    throw new TrialLimitExceededException();
}

// 不推荐：显而易见的注释
// 设置用户名为"admin"
user.setName("admin");

// 推荐：解释复杂算法
// 使用快速排序算法，时间复杂度 O(n log n)
Arrays.sort(users, Comparator.comparing(SysUser::getUserName));
```

## 异常处理规范

### 异常分类

#### 检查异常 vs 运行时异常
- 检查异常：可预期的错误，调用者必须处理
- 运行时异常：程序错误，通常不应该被捕获

```java
// 推荐：自定义业务异常
public class UserNotFoundException extends RuntimeException {
    public UserNotFoundException(Long userId) {
        super("User not found with ID: " + userId);
    }
}

// 推荐：使用检查异常处理可预期的错误
public class InvalidEmailException extends Exception {
    public InvalidEmailException(String email) {
        super("Invalid email format: " + email);
    }
}
```

### 异常处理最佳实践

#### 异常捕获和处理
```java
// 推荐：具体异常处理
try {
    userService.createUser(user);
} catch (DuplicateUserException e) {
    logger.warn("User already exists: {}", user.getEmail());
    return AjaxResult.error("用户已存在");
} catch (InvalidEmailException e) {
    logger.error("Invalid email format: {}", user.getEmail());
    return AjaxResult.error("邮箱格式不正确");
}

// 不推荐：捕获通用异常
try {
    userService.createUser(user);
} catch (Exception e) {
    // 处理所有异常，难以调试
}
```

#### 资源管理
```java
// 推荐：使用 try-with-resources
try (FileInputStream fis = new FileInputStream(file);
     BufferedReader reader = new BufferedReader(new InputStreamReader(fis))) {
    // 使用资源
} catch (IOException e) {
    logger.error("Error reading file", e);
}

// 推荐：确保资源释放
Connection connection = null;
try {
    connection = dataSource.getConnection();
    // 使用连接
} catch (SQLException e) {
    logger.error("Database error", e);
} finally {
    if (connection != null) {
        try {
            connection.close();
        } catch (SQLException e) {
            logger.error("Error closing connection", e);
        }
    }
}
```

## 日志规范

### 日志级别使用

#### 日志级别定义
- **ERROR**: 系统错误，需要立即处理
- **WARN**: 警告信息，可能影响系统功能
- **INFO**: 重要的业务流程信息
- **DEBUG**: 调试信息，仅在开发环境使用
- **TRACE**: 详细的跟踪信息

```java
// 推荐：合理使用日志级别
public void processOrder(SysUser user) {
    logger.info("Processing user: {}", user.getUserId());

    try {
        // 业务逻辑
        validateUser(user);

        logger.info("User processed successfully: {}", user.getUserId());
    } catch (ValidationException e) {
        logger.warn("User validation failed: {}", e.getMessage());
        throw e;
    } catch (Exception e) {
        logger.error("Unexpected error processing user: {}", user.getUserId(), e);
        throw new BusinessException("处理用户失败", e);
    }
}
```

日志配置参考 [application.yml](../../../ruoyi-admin/src/main/resources/application.yml#L34-L38)：
```yaml
# 日志配置
logging:
  level:
    com.ruoyi: debug
    org.springframework: warn
```

### 日志格式规范

#### 日志消息格式
- 使用结构化日志格式
- 包含必要的上下文信息
- 避免敏感信息泄露

```java
// 推荐：结构化日志
logger.info("User login successful - userId: {}, ip: {}, timestamp: {}",
           userId, clientIp, Instant.now());

// 推荐：包含业务上下文
logger.warn("Operation failed - userId: {}, operation: {}, reason: {}",
           userId, operation, failureReason);

// 不推荐：缺少上下文信息
logger.info("Login successful");
logger.warn("Operation failed");
```

## 测试代码规范

### 测试命名规范

#### 测试类命名
- 测试类名以"Test"结尾
- 测试类应该与被测试类在同一个包下

```java
// 推荐
public class SysUserServiceTest { }
public class SysUserMapperTest { }
```

#### 测试方法命名
- 使用描述性的测试方法名
- 遵循"should[期望结果]_when[条件]"格式

```java
// 推荐
@Test
public void shouldReturnUser_whenValidUserIdProvided() { }

@Test
public void shouldThrowException_whenInvalidEmailProvided() { }

@Test
public void shouldCreateUser_whenValidUserDataProvided() { }
```

### 测试结构规范

#### 测试方法结构
```java
@Test
public void shouldReturnUser_whenValidUserIdProvided() {
    // Given - 准备测试数据
    Long userId = 1L;
    SysUser expectedUser = new SysUser();
    expectedUser.setUserId(userId);
    when(userMapper.selectUserById(userId)).thenReturn(expectedUser);

    // When - 执行被测试的方法
    SysUser actualUser = userService.selectUserById(userId);

    // Then - 验证结果
    assertThat(actualUser.getUserId()).isEqualTo(userId);
    verify(userMapper).selectUserById(userId);
}
```

### Mock 使用规范

#### Mock 对象使用
```java
// 推荐：使用 Mockito 进行 Mock
@ExtendWith(MockitoExtension.class)
class SysUserServiceTest {
    @Mock
    private SysUserMapper userMapper;

    @InjectMocks
    private SysUserServiceImpl userService;

    @Test
    public void shouldCreateUser_whenValidUserData() {
        // Given
        SysUser user = new SysUser();
        user.setUserName("test");
        when(userMapper.insertUser(any(SysUser.class))).thenReturn(1);

        // When
        int result = userService.insertUser(user);

        // Then
        assertThat(result).isEqualTo(1);
        verify(userMapper).insertUser(user);
    }
}
```

## 安全编码规范

### 输入验证

#### 参数验证
```java
// 推荐：使用 Bean Validation
public class UserCreateRequest {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 3, max = 20, message = "用户名长度必须在 3-20 个字符之间")

    @Email(message = "邮箱格式不正确")
    @NotBlank(message = "邮箱不能为空")

// 推荐：手动验证
public void validateUser(SysUser user) {
    if (user == null) {
        throw new IllegalArgumentException("用户对象不能为 null");
    }
    if (StringUtils.isBlank(user.getUserName())) {
        throw new IllegalArgumentException("用户名不能为空");
    }
}
```

### 敏感信息处理

#### 密码处理
```java
// 推荐：使用 BCrypt 加密密码
@Service
public class PasswordService {
    private final BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();

    public String encodePassword(String rawPassword) {
        return passwordEncoder.encode(rawPassword);
    }

    public boolean matches(String rawPassword, String encodedPassword) {
        return passwordEncoder.matches(rawPassword, encodedPassword);
    }
}

// 不推荐：明文存储密码
user.setPassword("plaintextpassword"); // 安全风险
```

#### 日志安全
```java
// 推荐：避免记录敏感信息
logger.info("User login successful - userId: {}", userId); // 不记录密码

// 不推荐：记录敏感信息
logger.info("User login - username: {}, password: {}", username, password); // 安全风险
```

```properties
# sonar-project.properties
sonar.projectKey=ruoyi
sonar.projectName=RuoYi

sonar.java.binaries=target/classes

sonar.java.pmd.reportPaths=target/reports/pmd/main.xml
```
