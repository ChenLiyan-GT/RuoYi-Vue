## 概述

本文档定义了 RuoYi-Vue 项目的编码规范和最佳实践，旨在确保代码质量、可维护性和团队协作效率。所有开发人员必须严格遵循本规范，通过代码审查和自动化工具确保规范的执行。

### 核心原则
- **可读性优先**: 代码应该易于理解和维护
- **一致性**: 保持代码风格和结构的一致性
- **简洁性**: 避免过度复杂的设计和实现
- **安全性**: 遵循安全编码最佳实践
- **性能**: 在保证可读性的前提下优化性能

## 代码风格规范

### 基本格式规范

#### 缩进和空格
- 使用空格进行缩进，每个缩进级别为4个空格
- 行尾不允许有空格
- 文件末尾保留一个空行

#### 大括号规范

RuoYi 项目采用**左大括号换行**风格，类声明、方法声明、控制语句的左大括号均独占一行：

```java
// 项目实际风格：左大括号换行
public class SysUserController extends BaseController
{
    @RequiresPermissions("system:user:list")
    @PostMapping("/list")
    @ResponseBody
    public TableDataInfo list(SysUser user)
    {
        startPage();
        List<SysUser> list = userService.selectUserList(user);
        return getDataTable(list);
    }
}
```

#### 空行规范
- 类成员之间使用一个空行分隔
- 方法之间使用一个空行分隔
- 逻辑块之间使用空行提高可读性
- 导入语句分组，组间使用空行分隔

### 导入语句规范

导入语句按以下顺序分组，组间使用空行分隔：

```java
// 1. Java标准库
import java.util.List;
import java.util.stream.Collectors;

// 2. 第三方库
import org.apache.shiro.authz.annotation.RequiresPermissions;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Controller;

// 3. 项目内部包
import com.ruoyi.common.annotation.Log;
import com.ruoyi.common.core.controller.BaseController;
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.system.service.ISysUserService;
```

> 参考：[SysUserController.java](../../ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java) 的导入顺序

## 命名规范

### 类命名规范

#### 类名
- 使用PascalCase（首字母大写的驼峰命名）
- 类名应该是名词，具有描述性
- 实体类以 `Sys` 前缀标识系统模块（如 `SysUser`、`SysRole`、`SysDept`）

```java
// 项目实际命名
public class SysUserController extends BaseController { }
public class SysUserServiceImpl implements ISysUserService { }
public class SysUserMapper { }
```

#### 接口命名
- Service 接口以 `I` 前缀 + 实体名 + `Service` 命名
- 接口实现类以实体名 + `ServiceImpl` 命名
- Mapper 接口以实体名 + `Mapper` 命名

```java
// Service 接口
public interface ISysUserService { }

// Service 实现
public class SysUserServiceImpl implements ISysUserService { }

// Mapper 接口
public interface SysUserMapper { }
```

> 参考：[ISysUserService.java](../../ruoyi-system/src/main/java/com/ruoyi/system/service/ISysUserService.java)、[SysUserServiceImpl.java](../../ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java)

### 方法命名规范

#### 方法名
- 使用camelCase（首字母小写的驼峰命名）
- 查询方法以 `select` 前缀开头
- 新增方法以 `insert` 前缀开头
- 修改方法以 `update` 前缀开头
- 删除方法以 `delete` 前缀开头
- 校验方法以 `check` 前缀开头
- 布尔方法使用 `is`、`has` 等前缀

```java
// 查询
public List<SysUser> selectUserList(SysUser user);
public SysUser selectUserByLoginName(String userName);

// 新增
public int insertUser(SysUser user);

// 修改
public int updateUser(SysUser user);

// 删除
public int deleteUserByIds(Long[] ids);

// 校验
public boolean checkLoginNameUnique(SysUser user);
```

> 参考：[SysUserMapper.java](../../ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysUserMapper.java) 的方法命名

### 变量命名规范

#### 变量名
- 使用camelCase
- 变量名应该具有描述性
- 避免使用单字母变量名（除了循环变量）

#### 常量命名
- 使用UPPER_SNAKE_CASE
- 常量名应该具有描述性
- 使用 `public static final` 修饰

```java
// 项目实际常量命名
public static final String UTF8 = "UTF-8";
public static final String SUCCESS = "0";
public static final String FAIL = "1";
public static final String LOGIN_SUCCESS = "Success";
public static final int MAX_LOGIN_ATTEMPTS = 5;
```

> 参考：[Constants.java](../../ruoyi-common/src/main/java/com/ruoyi/common/constant/Constants.java)

### 方法结构规范

#### 方法长度
- 单个方法不宜过长，如果方法过长应考虑拆分为多个小方法
- 每个方法只做一件事

#### 参数规范
- 方法参数不宜过多
- 多参数 Mapper 方法使用 `@Param` 注解标注参数名

```java

public int updateUserAvatar(@Param("userId") Long userId, @Param("avatar") String avatar);
public int resetUserPwd(@Param("userId") Long userId, @Param("password") String password, @Param("salt") String salt);
```

### 实体继承规范

- 普通实体继承 [BaseEntity](../../ruoyi-common/src/main/java/com/ruoyi/common/core/domain/BaseEntity.java)，包含 searchValue/createBy/createTime/updateBy/updateTime/remark/params
- 树形结构实体继承 [TreeEntity](../../ruoyi-common/src/main/java/com/ruoyi/common/core/domain/TreeEntity.java)（extends BaseEntity），额外包含 parentName/parentId/orderNum/ancestors

### 响应封装规范

- Controller 方法返回页面视图时返回 `String`（视图名称）
- AJAX 请求返回 [AjaxResult](../../ruoyi-common/src/main/java/com/ruoyi/common/core/domain/AjaxResult.java)（`{code, msg, data}`），状态码：SUCCESS(0)/WARN(301)/ERROR(500)
- 分页查询返回 `TableDataInfo`（`{total, rows, code, msg}`）
- REST API 返回 [R\<T\>](../../ruoyi-common/src/main/java/com/ruoyi/common/core/domain/R.java) 泛型强类型响应（`{code, msg, data}`）
- Controller 使用 `toAjax(int rows)` 将影响行数转为 AjaxResult

## 注释规范

### JavaDoc规范

#### 类注释
- 每个类必须有类级别注释
- 包含类的功能说明和 `@author` 标签

```java
/**
 * 用户信息
 * 
 * @author ruoyi
 */
@Controller
@RequestMapping("/system/user")
public class SysUserController extends BaseController
{
```

#### 方法注释
- Service 接口方法必须有完整的 JavaDoc，包含 `@param` 和 `@return`
- Controller 方法使用简短注释说明功能

```java
// Service 接口方法注释（完整 JavaDoc）
/**
 * 根据条件分页查询用户列表
 * 
 * @param user 用户信息
 * @return 用户信息集合信息
 */
public List<SysUser> selectUserList(SysUser user);

// Controller 方法注释（简短说明）
/**
 * 新增用户
 */
@RequiresPermissions("system:user:add")
@GetMapping("/add")
public String add(ModelMap mmap)
{
```

### 行内注释规范

- 解释"为什么"而不是"做什么"
- 避免显而易见的注释
- 注释应该与代码同步更新

```java
// 推荐：解释业务逻辑
// 获取用户所属的角色列表
List<SysRole> roles = roleService.selectRolesByUserId(userId);

// 推荐：解释特殊处理
// 试用期用户有特殊限制
if (user.isInTrialPeriod() && user.getUsageCount() > TRIAL_LIMIT) {
    throw new TrialLimitExceededException();
}
```

## 异常处理规范

### 异常体系

RuoYi 项目异常体系以 [BaseException](../../ruoyi-common/src/main/java/com/ruoyi/common/exception/base/BaseException.java) 为基类，继承自 `RuntimeException`，支持模块（module）、错误码（code）、参数（args）和默认消息（defaultMessage），并通过 `MessageUtils` 支持国际化：

```
RuntimeException
├── BaseException              # 基础异常（module/code/args/defaultMessage，支持 i18n）
│   └── file/                  # 文件异常
│       ├── FileException
│       ├── FileSizeLimitExceededException
│       ├── FileNameLengthLimitExceededException
│       ├── FileUploadException
│       └── InvalidExtensionException
├── ServiceException           # 业务异常（final 类，message + detailMessage）
├── GlobalException            # 全局异常
├── DemoModeException          # 演示模式异常
├── UtilException              # 工具异常
└── user/                      # 用户相关异常
    ├── UserException
    ├── UserNotExistsException
    ├── UserPasswordNotMatchException
    ├── UserPasswordRetryLimitCountException
    ├── UserPasswordRetryLimitExceedException
    ├── CaptchaException
    ├── RoleBlockedException
    ├── UserBlockedException
    └── BlackListException
```

> 参考：[exception 包](../../ruoyi-common/src/main/java/com/ruoyi/common/exception/)

### 异常处理最佳实践

#### 业务异常抛出
- 业务校验失败时抛出 `ServiceException`，携带用户可读的错误消息
- 不允许在业务代码中直接抛出 `BaseException`

```java
// 推荐：使用 ServiceException
if (!userService.checkLoginNameUnique(user))
{
    return error("新增用户'" + user.getLoginName() + "'失败，登录账号已存在");
}

// 推荐：Service 层抛出业务异常
throw new ServiceException("用户不存在");
```

#### 全局异常处理

[GlobalExceptionHandler](../../ruoyi-framework/src/main/java/com/ruoyi/framework/web/exception/GlobalExceptionHandler.java) 统一处理所有异常，开发者无需在 Controller 中手动 try-catch：

| 异常类型 | 处理方式 |
|----------|----------|
| `ServiceException` | 区分 AJAX/非 AJAX，返回 AjaxResult 或错误页面 |
| `AuthorizationException` | 区分 AJAX/非 AJAX，返回权限错误或跳转 unauth 页面 |
| `BindException` | 返回第一个校验错误消息 |
| `DemoModeException` | 返回"演示模式，不允许操作" |
| `RuntimeException` | 记录错误日志，返回 AjaxResult |
| `Exception` | 记录错误日志，返回 AjaxResult |

## 日志规范

### 日志声明

- Service 实现类使用 `private static final Logger log` 声明日志对象
- Controller 继承 [BaseController](../../ruoyi-common/src/main/java/com/ruoyi/common/core/controller/BaseController.java)，直接使用 `protected final Logger logger`

```java
// Service 实现类
public class SysUserServiceImpl implements ISysUserService
{
    private static final Logger log = LoggerFactory.getLogger(SysUserServiceImpl.class);
}

// Controller（继承 BaseController，已内置 logger）
public class SysUserController extends BaseController
{
    // 直接使用 logger
}
```

### 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| ERROR | 系统错误，需要立即处理 | `log.error("请求地址'{}',发生未知异常.", requestURI, e);` |
| WARN | 警告信息，可能影响系统功能 | 密码错误次数计数 |
| INFO | 重要的业务流程信息 | 操作日志异步记录 |
| DEBUG | 调试信息，仅在开发环境使用 | 开发环境 `com.ruoyi` 级别为 debug |

> 日志级别配置见 [application.yml](../../ruoyi-admin/src/main/resources/application.yml)：`com.ruoyi: debug`（开发）、[logback.xml](../../ruoyi-admin/src/main/resources/logback.xml)：`com.ruoyi` level info（运行时）

### 日志格式

项目日志输出格式为：

```
%d{HH:mm:ss.SSS} [%thread] %-5level %logger{20} - [%method,%line] - %msg%n
```

包含时间、线程名、日志级别、Logger名、方法名、行号和消息。

### 日志文件

| 文件 | 内容 | 保留天数 |
|------|------|----------|
| sys-info.log | INFO 级别日志 | 60天 |
| sys-error.log | ERROR 级别日志 | 60天 |
| sys-user.log | 用户操作日志 | 60天 |

> 配置详见 [logback.xml](../../ruoyi-admin/src/main/resources/logback.xml)

### 操作日志

使用 [@Log](../../ruoyi-common/src/main/java/com/ruoyi/common/annotation/Log.java) 注解记录操作日志，通过 [AsyncManager](../../ruoyi-framework/src/main/java/com/ruoyi/framework/manager/AsyncManager.java) 异步写入数据库，不影响主流程性能：

```java
@Log(title = "用户管理", businessType = BusinessType.INSERT)
@RequiresPermissions("system:user:add")
@PostMapping("/add")
@ResponseBody
public AjaxResult addSave(@Validated SysUser user)
{
    // ...
}
```

`businessType` 取值参见 `BusinessType` 枚举：INSERT/UPDATE/DELETE/GRANT/EXPORT/IMPORT/OTHER 等。

## 安全编码规范

### 密码安全

- 密码加密方式：`Md5Utils.hash(loginName + password + salt)`
- 盐值生成：`ShiroUtils.randomSalt()` 使用 `SecureRandomNumberGenerator` 生成6位随机盐
- 密码错误次数限制：默认5次锁定10分钟（通过 EhCache 计数，配置项 `user.password.maxRetryCount`）

```java
// 加密流程
user.setSalt(ShiroUtils.randomSalt());
user.setPassword(passwordService.encryptPassword(user.getLoginName(), user.getPassword(), user.getSalt()));
```

### XSS 防护

- [XssFilter](../../ruoyi-common/src/main/java/com/ruoyi/common/xss/XssFilter.java) 默认开启，过滤 POST/PUT 请求
- GET 和 DELETE 请求不过滤
- 排除链接配置：`/system/notice/*`
- 匹配链接配置：`/system/*,/monitor/*,/tool/*`

```yaml
# application.yml 配置
xss:
  enabled: true
  excludes: /system/notice/*
  urlPatterns: /system/*,/monitor/*,/tool/*
```

### 数据脱敏

使用 [@Sensitive](../../ruoyi-common/src/main/java/com/ruoyi/common/annotation/Sensitive.java) 注解对敏感字段进行脱敏，支持7种类型：

| 类型 | 说明 | 脱敏规则 |
|------|------|----------|
| USERNAME | 姓名 | 第2位星号替换 |
| PASSWORD | 密码 | 全部用*代替 |
| ID_CARD | 身份证 | 中间10位星号替换 |
| PHONE | 手机号 | 中间4位星号替换 |
| EMAIL | 邮箱 | 仅显示首字母和@后地址 |
| BANK_CARD | 银行卡 | 保留最后4位 |
| CAR_LICENSE | 车牌号 | 包含普通/新能源车辆 |

### 数据权限

使用 [@DataScope](../../ruoyi-common/src/main/java/com/ruoyi/common/annotation/DataScope.java) 注解实现数据权限过滤，支持5种范围：

- 全部数据权限
- 自定义数据权限
- 本部门数据权限
- 本部门及以下数据权限
- 仅本人数据权限

```java
// Service 方法上标注 @DataScope
@Override
@DataScope(deptAlias = "d", userAlias = "u")
public List<SysUser> selectUserList(SysUser user)
{
    return userMapper.selectUserList(user);
}
```

`deptAlias` 和 `userAlias` 对应 SQL 中部门表和用户表的别名，AOP 切面会自动在 SQL 末尾追加权限过滤条件。

### 权限控制

- 使用 Shiro 的 `@RequiresPermissions` 注解控制接口权限
- 权限标识格式：`模块:功能:操作`（如 `system:user:list`、`system:user:add`、`system:user:edit`、`system:user:remove`）
- 免认证接口使用 [@Anonymous](../../ruoyi-common/src/main/java/com/ruoyi/common/annotation/Anonymous.java) 注解，自动注入 Shiro 过滤链

### 防重复提交

使用 [@RepeatSubmit](../../ruoyi-common/src/main/java/com/ruoyi/common/annotation/RepeatSubmit.java) 注解防止表单重复提交：

```java
@RepeatSubmit(interval = 5000, message = "不允许重复提交，请稍后再试")
@PostMapping("/submit")
@ResponseBody
public AjaxResult submit(DataForm form)
{
    // ...
}
```

### CSRF 防护

CSRF 防护默认关闭，可通过配置开启：

```yaml
# application.yml
csrf:
  enabled: false
  whites: /druid
```

### 演示模式

当 `ruoyi.demoEnabled=true` 时，所有写操作将抛出 `DemoModeException`，由全局异常处理器返回"演示模式，不允许操作"提示。

## 代码审查规范

### 审查检查清单

#### 功能性检查
- [ ] 代码是否实现了预期功能
- [ ] 边界条件是否得到正确处理
- [ ] 异常情况是否得到适当处理
- [ ] 数据权限是否正确配置（@DataScope 的 deptAlias/userAlias）

#### 代码质量检查
- [ ] 代码是否遵循命名规范（IXxxService / XxxServiceImpl / XxxMapper / XxxController）
- [ ] 代码结构是否清晰合理（Controller → Service → Mapper 分层）
- [ ] 注释是否充分且准确
- [ ] 是否存在代码重复

#### 安全性检查
- [ ] 输入验证是否充分（@Validated / 手动校验）
- [ ] 敏感信息是否得到保护（@Sensitive 脱敏 / 日志不记录密码）
- [ ] 权限控制是否正确（@RequiresPermissions）
- [ ] 是否存在 SQL 注入风险（Mapper XML 使用 `#{}` 而非 `${}`，数据权限 `${params.dataScope}` 除外）

#### RuoYi 特有检查
- [ ] 新增业务是否遵循建表 → Domain → Mapper → Service → Controller → 模板 → 菜单的流程
- [ ] 操作日志是否添加 @Log 注解
- [ ] 分页查询是否调用 `startPage()` 方法
- [ ] 响应是否使用 AjaxResult / TableDataInfo / R\<T\> 封装
- [ ] 演示模式下写操作是否受限

### 审查流程

1. **自检**: 开发者完成代码自检
2. **工具检查**: 运行 `mvn clean compile -B` 确保编译通过
3. **同行审查**: 至少一名同事进行代码审查
4. **修改完善**: 根据审查意见修改代码
5. **最终确认**: 审查者确认修改结果
